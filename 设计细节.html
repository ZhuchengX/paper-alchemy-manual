PAPER ALCHEMY · 设计细节

每个模块怎么运转

说明书主页只放你要用的部分；这里是各模块的完整机制，原文从主页移过来，没删。状态见主页 进度表。

B1 · 验矿卡

① 输入侧：先验矿

输入是一大批论文，人写的或 autoresearch 产出的都行。先两轮筛选：摘要初筛给 solid 分，再按 PDF 首页印出的机构二筛；然后按共享作者分独立来源组，防止同一拨人刷屏。已实现 · B1 验矿卡：抽取后、建库前生成 triage/solidity.csv，逐篇报告内部不一致、代码公开和来源 ID 是否见于全文；保留命中原句供复核，不造总分、不设默认阈值，建库过滤须显式打开开关。已实现 · B9 启发池：另用 ScholarCatalyst 作者理由（rationale）蒸馏出的构思动作当算子，找表面不相关、但能启发的论文，并让 13 个算子各出、多个算子组合出 idea 草稿，先把多样性做起来；单独成池，不进统计。

B2 · 逐候选审查

2026-10-23 起（蓝图 B2）审查拆成两层：pipeline/review_loop.py 给每个候选单独派一个 critic（只看这一条，判 VALIDATED / REVISE / DROP），REVISE 的交一个新 agent 按 critic 列的改动改写，最多 2 轮，第 2 轮后仍 REVISE 就记 DROP，写进 dropped_routes.md；最后一个 judge 只从 VALIDATED 里聚类、排序、选终稿，不能把被淘汰的捞回来。旧的单 agent 04_review 留作后备。

B4 · 五角色新眼审稿

成稿之后（2026-10-24 起，蓝图 B4）还有一道新眼审稿：pipeline/review5_loop.py 请方法学家、领域专家、怀疑者、实践者、写作编辑五个角色，只读成稿和语料、不看任何作者侧材料，每条意见都要指到编号段落；一个修订 agent 只能改被指出的段落，脚本逐段比对，越界即判 FAIL；最后五个角色各自终审，判 ACCEPT 或 REOPEN，REOPEN 交你决定是否回成文。

B5 · 架构师三棱镜 + 禁说清单

成文之前（2026-10-24 起，蓝图 B5）先过「架构师三棱镜」：pipeline/architect_loop.py 先不花钱，从 final_scores.json 生成禁说清单（边界结论不许写成机制或定律、猜想必须写成猜想、指路测试的数字不许引用、作者自家方法一去掉覆盖率就变的必须点明）；再请 novelty / narrative / impact 三个架构师各出一份论文骨架，它们只改顺序和讲法，不增删结论；一个 decider 选一份、补几条措辞规则。三份骨架并排在 architecture/maps.html 里交你选（闸⑥）。写作 agent 按选中的骨架写，写完 check.py paper 用 check_claims.py 逐条核对，出现禁说即 FAIL。思路借自 TPL 的 argument_architect / argument_select 与 claim_calibration.md；TPL 的论证审计员（argument_audit）这里没做，留给 B6/B7。

B6 · 可行性闸 + 扩展牌组

架构师之前（2026-10-24 起，蓝图 B6）先过可行性闸和扩展牌组：pipeline/expand_deck.py 不花钱，先判这一轮撑不撑得起金子。没有一条 G 有至少 2 个独立组的计数支撑，就判 KILL，写 deck/null_memo.md「这一轮不出金子，原因是……」，不再成文；撑得起的 G 全是边界，就判 PASS_DESCRIPTIVE_ONLY，只写描述性论文。然后给每条 G 发 7 张扩展卡：留一组覆盖率、按格异质、机制、反例、发表偏倚、成本口径、闭卷对照。每张卡判 holds（不变）/ narrows（要加边界）/ descriptive_only / n_a / needs_call，判据只看结论会不会翻到 0.5 的另一侧，且子集里要有至少 2 个独立组。闭卷卡要花一次调用，只先渲染好提示词。你在 deck/deck.md 砍卡（闸⑦），留下的卡交给写作：narrows 写进该 G 的边界，其余进局限与开放问题。思路借自 TPL 的约 7 张扩展卡与 KILL 出口。

B7 · 编排器

或者一条命令串起来（2026-10-24 起，蓝图 B7）：pipeline/orchestrate.py 按 stages.json 的阶段顺序、pipeline/flow.json 写的每阶段做法逐个执行。每个阶段都要过闸门，碰到人工闸就停下等你回答。

python3 -I pipeline/orchestrate.py run RUN_DIR                    # interactive：停在 ①②③⑦⑥ 等你
python3 -I pipeline/orchestrate.py run RUN_DIR --answer ⑦=ok      # 认了，接着跑；=no:<原因> 则停住
python3 -I pipeline/orchestrate.py run RUN_DIR --mode auto        # 全自动：人工闸记 auto-approved
python3 -I pipeline/orchestrate.py status RUN_DIR                 # 每个阶段的状态
#   可选阶段要点名才跑：--with S19,S22；只跑到某步：--until S20；跑完某步就停：--stop-after S12
  • 状态：记在 traces/state.json，流水记在 traces/orchestrate.log.jsonl。
  • 跳过：每个阶段算一个指纹（它渲染的模板、调用的脚本、上游产物）。指纹没变就跳过；改了哪个模板或脚本，只重跑用到它的阶段，以及产物因此变了的下游阶段。
  • KILL：可行性闸判 KILL 时，流程停在 S18b，不往下成文。
  • 手动阶段：数字机核、新眼审稿、评估这几步还要人做，编排器停下说明要做什么，做完再跑同一条命令。
  • 自检：--fake-agent 模式不花钱。agent 和联网步骤换成拷贝 fixture，脚本和闸门照常跑。pipeline/_fixtures/selftest_orchestrate.py 在 3 篇小语料上验收：从头跑到成文、kill -9 后续跑、改模板只重跑成文、KILL 停住，8 项全过。

和 TPL 的差距：TPL 的闸在 TUI 里弹清单、回车放行，还有全自动模式。我们的闸由 orchestrate.py 统一处理：interactive 模式停下，打印问题和要看的文件，你用 --answer 回答；auto 模式直接放行，并记为 auto-approved。TUI 弹窗没有做，命令行就是界面。已实现 · B7

B8 · 交付包

最后一步打包交付（2026-10-24 起，蓝图 B8）：pipeline/deliver.py pack 把正文、PDF、证据包和最终报告打成一个 .tar.gz。证据包里有打分要用的 db 表、候选、打分脚本、数字机核的 registry，以及 registry 指到的每个文件；打分结果本身不带。reproduce.sh 在包里重新打分，再逐条核对正文数字，生成逐数字对照表 evidence/check/check.md。deliver.py verify 把包解到空目录，在空环境变量、且禁止读 /Users 的沙箱里跑 reproduce.sh，相当于换一台干净机器：每个数字都要 MATCH，重新打分的结果要和原文件一致。REPORT.md 把数字分成两类：从 db 重新算出的，和读随包输入的（抽取、候选里写下的数、菜单常量）；后一类只能证明正文抄对了，证明不了输入本身对。摘要可以交给没参与写作的 reader 重写（templates/21_abstract_reader.md，1 次 codex），不许含数字，deliver.py abstract-check 用和数字机核同一套数字定义检查。v4 的包里 214 个数字全部复算通过。

B9 · 启发池

④ 启发池（不用你填） 已实现 · B9 启发池

菜单定下中心问题后，流水线自己建一个启发池（流程图模块 1 的 S00a），用来让有信息量的想法尽量都冒出来：

  • 算子从哪来：ScholarCatalyst 里 184 位作者亲笔写的 1,348 条「我当初为什么受这篇启发」的理由（rationale）。每条理由拆成三槽：前作做出了什么 / 我拿走什么、搬到哪 / 凭什么相信会成。661 条 core 理由逐条标成 13 种构思动作（M1–M9、M13–M16）或 8 种不出卡的引用角色（C1–C8），构思动作例如 M1 跨域移植、M2 换挂点、M4 解释现象、M13 问题重述（skill catalyst-ideation/SKILL.md §0、§5；范例库 references/moves_bank_v1.md）。
  • 怎么当算子用：每个动作配一条真实理由当范例，把中心问题改写成一组检索词，去找表面不直接相关的论文。例：问题「聚合器读 K 条轨迹为什么丢掉正确证据」，按 M1 改写成「弱监督里多个标注源的相关误差」，找到 2603.00039；按关键词搜原题找不到它（SKILL.md §8，core 469）。
  • 为什么要做：作者实际用到的催化剂论文，49.5% 来自本领域之外（ScholarCatalyst 论文 §5）。
  • 算子还出 idea 草稿（2026-10-23 与师兄讨论后定）：
    • 单算子：13 个算子轮流上，每个都按中心问题出一份 idea 草稿。
    • 算子组合：agent 按中心问题挑几组算子组合，每组出一份草稿，并写明先用哪个、后用哪个、为什么这样组合。最多 13 组（上限可调），不穷举全部 78 种两两组合。组合的是两个动作；M9「组合互补」组合的是两篇论文，不是一回事。
    • 多投入调用，先发散：这一步用订阅额度并行多个 agent。验收看多样性：草稿去重后剩几份、覆盖了几个算子。
    • 草稿不是正式卡：只用来启发。流程末尾的构思出卡（S25）照旧，正式卡仍要过撞车检查和信心打分。
  • 放在哪：单独的 RUN_DIR/inspire/：papers.jsonl 放启发论文，每篇记下是哪个算子、哪条检索词找到的；drafts/ 放 idea 草稿，每份记下用了哪个或哪组算子。不进抽取和数据库，金子论文的统计数字只来自主题论文；启发池现在只交给提议者（S12）当镜头，构思出卡（S25）还没接上。
  • 怎么跑：编排器跑到 S00a 自动做完，一轮约 27 次 codex（13 份单算子 + 1 次挑组合 + 至多 13 份组合，组合上限用 --set MAX_COMBOS=N 调）。只找 SPLIT 之前的论文；菜单里留作检验的论文一篇都不许出现。跑完先看 inspire/INDEX.md（每份草稿的题目和找到几篇论文）和 inspire/diversity.md（去重后剩几份、覆盖几个算子、几成论文不在本轮语料里）。旧菜单没有「Central question」时用「Dish」代替并打出警告。
  • 还没做 🔭 B9 另一半：按菜单详略分三档、路线数随之变（3 / 4–5 / 6）。
  • 别和「算子 DSL」混：这里的「构思算子」指 ScholarCatalyst 的构思动作；开头「② 中间侧」卡片和下文「它怎么思考」里的「算子程序 / 算子 DSL」（Gen / Comm / Agg…）是描述方法结构的记法，两者无关。

7 个闸 · 每个的细节

★ 闸① · 菜单拍板

定选题、读者、时间窗、纳入排除、锁定答案。这一步决定后面所有 agent 看到什么，跑起来以后不再改。只回答一个问题：「菜单这样定，跑起来后不再改，可以吗？」

★ 闸② · 筛选边界

看 triage/lab_review_lenient.csv（宽松机构清单），决定删谁；需要补读图表的论文列在 figure_pass_candidates.tsv。只回答一个问题：「这些边缘论文算不算 solid？」

★ 闸③ · 终稿结论过目

审查后的 synthesis/final_candidates.json 加上打分。需要你定口径的分歧写在台账里，例如 2026-10-22 你定的「采样基线默认只认纯投票」。只回答一个问题：「每条 G 的边界你认不认？」

★ 闸④ · 出卡勾选与花钱

棋盘出卡后，打开 chessboard/decision_page.html 勾选，得到 decisions.json。凡是要调付费 API 的实验，先过 13_preapproval 跑前配置卡：本次配置、原论文配置、差异与理由、预算。等你同意才跑。只回答一个问题：「哪几张卡做？（花钱的先看配置卡）」

★ 闸⑦ · 哪几张扩展卡进论文（成文前）

打开 synthesis/…/deck/deck.md：一行一条 G，七列是七张卡的结果；细节在 deck/<G>/cards.md。默认全留；不想写进论文的卡用 expand_deck.py cut <RUN_DIR> <G> <卡> 砍掉。可行性闸判 KILL 时不到这一步，先读 deck/null_memo.md。只回答一个问题：「哪几张扩展卡进论文？」

★ 闸⑥ · 用哪份骨架写（成文前）

打开 synthesis/…/architecture/maps.html，三份骨架并排，最上面是 decider 的选择和理由；claim_calibration.md 是每条 G 能说什么、不能说什么。同意就不用动；想换就跑 architect_loop.py pick <RUN_DIR> <prism>。只回答一个问题：「用哪份骨架写？」（编号按加入先后，时间上在闸⑤之前。）

★ 闸⑤ · 是不是真金

读终稿 PDF 和决策指南。只回答一个问题：「这篇是不是值得精读的金子？」改动意见写进 paper/v3/changelog.md 的下一版。

菜单与建运行目录 · 详版

照 config/menu.md 的格式写一份菜单，包括：

  • 选题
  • 中心问题：一句话，外行一分钟能听懂，并说清什么算答上了；子问题都挂在它下面，偏题的进剩菜。审查步用它判终稿集合有没有跑题（凌杨 §4.2a、§3.7）
  • 读者与注意力预算
  • 时间窗 YYYY-MM-DD .. YYYY-MM-DD
  • 纳入 / 排除标准
  • 锁定答案的论文编号，写在 “reserved for evaluation” 后面

然后建运行目录：

python3 pipeline/init_run.py ~/runs/run4 --run-id run4_xxx --menu ~/runs/menu_run4.md \
    --split 2025-07-01 --forbid ~/HITSZ/paper_alchemy_run3 --agent-models "claude-opus-5-5=2026-06"
  • 它会把 scripts/*.py（全部）、config/schema.md、config/db_guide.md、config/model_prices* 拷进运行目录，成为这一轮的冻结快照。
  • 它会写 run.json，后面所有提示词的占位符都从这里取。
  • --forbid 列出 agent 不许读的目录。pipeline 目录本身总在禁读名单里，因为它装着别的轮的结论和答案键。
  • 答案文件放在运行目录之外，只有最后的评估 agent 能读。
