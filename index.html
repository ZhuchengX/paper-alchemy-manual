PAPER ALCHEMY · 用户使用说明书

把一大堆 autoresearch 论文，炼成一篇值得精读的 insight 论文

本说明书的章节结构照 Team Paper Lite 公开说明书一一对应，方便对照、找差距；内容全部是本仓库的真实流程。标 🔭 规划中 的是还没做的部分，编号对应蓝图 B0–B8（docs/research/pipeline泛化_20261023/blueprint_TPL对照.html）。

这是什么一句话讲清

论文炼金 = 文献采购员 ＋ 证据抽取员 ＋ 统计审查员 ＋ 写作伙伴，由你本机的 Claude Code 主线程按本手册逐阶段调度子 agent，加上一组 Python 脚本和闸门。你的工作不是读完几百篇论文，而是定选题、在关键决策点拍板、判断最后那篇是不是真金。

它的优化目标是注意力经济：N 篇论文 → m 篇必读（m 远小于 N）。输出必须是论文形态，并且抽象出更高层的通解，不是摘要或综述（CLAUDE.md「必须遵守的设计原则」第 1 条）。

① 输入侧：先验矿

输入是一大批论文，人写的或 autoresearch 产出的都行。先两轮筛选：摘要初筛给 solid 分，再按 PDF 首页印出的机构二筛；然后按共享作者分独立来源组，防止同一拨人刷屏。

② 中间侧：多炉并炼

每篇论文拆成「带条件的事实 ＋ 算子程序」。3–4 个提议 agent 从不同角度并行提出候选通解，互不读对方文件；打分器和审查 agent 负责筛选。巨人镜头（制度借鉴、构思动作、棋盘法）另出候选卡。

③ 控制权在你

选题与锁定答案、宽松机构的删减、终稿结论、出卡勾选、花钱前的配置卡，这几处都停下来等你。agent 只提议，不替你拍板。

④ 产出侧：成色可查

金子论文（英文全文 ＋ 中文正文 PDF）、决策指南、可视化页（地图、拼盘、结果页）。每条结论都带支撑行、独立组数、稳健性；正文只许引用语料内的论文，由闸门机器拦截。

这不是什么：它不是一键出论文的 SaaS，也不是「帮你想题目」的聊天框，更不是综述生成器。它是一条在你本机跑的、从一批论文到一篇通解论文的流水线。现在还没有一键编排脚本，由主线程照 pipeline/RUNBOOK.md 逐阶段推进（RUNBOOK §3）。🔭 B7 编排器

安装阶段常见报错

报错怎么办
FileNotFoundError: …/corpus/corpus.json（跑 check.py … extract 时）运行目录里还没有 corpus。先走采购阶段，或者在重抽这类场景下从源运行目录拷一份 corpus/corpus.json。
别人机器上提示词里的路径打不开没跑 localize_paths.sh。跑完用 --check 确认。
ModuleNotFoundError: pandaspip install pandas numpy。运行脚本统一用 python3 -I（隔离模式，避免读到当前目录下的同名模块）。
出 PDF 时中文是方块TeX 不完整，或缺 CJK 字体。用 TeX Live 完整版；pipeline/pdf/header.tex 里指定的字体本机要有。

跑第一轮动手

每一轮一个独立的运行目录。agent 只能读这个目录和全文目录，读不到别的轮次的结论和答案（RUNBOOK 开头）。

① 写菜单、建运行目录

照 config/menu.md 的格式写一份菜单，包括：

  • 选题
  • 读者与注意力预算
  • 时间窗 YYYY-MM-DD .. YYYY-MM-DD
  • 纳入 / 排除标准
  • 锁定答案的论文编号，写在 “reserved for evaluation” 后面

然后建运行目录：

python3 pipeline/init_run.py ~/runs/run4 --run-id run4_xxx --menu ~/runs/menu_run4.md \
    --split 2025-07-01 --forbid ~/HITSZ/paper_alchemy_run3 --agent-models "claude-opus-5-5=2026-06"
  • 它会把 scripts/*.py（全部）、config/schema.md、config/db_guide.md、config/model_prices* 拷进运行目录，成为这一轮的冻结快照。
  • 它会写 run.json，后面所有提示词的占位符都从这里取。
  • --forbid 列出 agent 不许读的目录。pipeline 目录本身总在禁读名单里，因为它装着别的轮的结论和答案键。
  • 答案文件放在运行目录之外，只有最后的评估 agent 能读。

② 逐阶段：渲染提示词 → 交给子 agent → 过闸门

# 例：抽取第 1 批（每个 agent 4–5 篇）
python3 pipeline/make_batches.py RUN_DIR --size 5 --ids RUN_DIR/triage/core_ids.txt
python3 pipeline/render.py RUN_DIR 02_extract IDS="2305.14325 2305.19118" BATCH=b1
#   → 提示词同时存进 RUN_DIR/traces/prompts/02_extract_b1.md（留痕）
#   → 主线程把整段交给子 agent（Agent 工具，model: opus）
python3 pipeline/check.py RUN_DIR extract          # 全部批次抽完后过闸

一次只推进一个阶段，过了闸门再进下一个。阶段顺序见下一节「它怎么思考」。

三类输入怎么填 · 带范例

① 选题与读者（菜单里必填）

选题：多次便宜调用 vs 一次贵调用——多 agent、并行采样、投票 / 聚合、辩论、自适应停止、test-time scaling。
读者：做 agent 系统的研究者；注意力预算：一篇 ≤ 4,500 词的正文。
时间窗：2023-01-01 .. 2026-10-19

② 纳入 / 排除（菜单里必填）

纳入：train-free；报告了算力或成本；有受控基线。
排除：只训练策略的论文、单链推理、综述、没有任务准确率的。

以上两段改写自 run3 的菜单口径（docs/07_第三轮运行记录_run3.md）。筛选模板 01b_triage.md:24-25 目前写死了其中一部分，🔭 泛化 T2 会改成从菜单读。

③ 锁定答案（菜单里必填）

挑几篇「人类后来公认的结论」论文，编号写进 reserved for evaluation。它们不进语料，也不让任何 agent 读到，最后用来检验金子论文有没有独立炼出同样的结论（CLAUDE.md 设计原则第 10 条）。

③ 跟跑 · 离开 · 回来取成果

  • 中途离开：每个阶段的产物都落在运行目录里，下次照 RUNBOOK 从没过闸的那个阶段接着做。现在没有自动 resume。🔭 B7
  • 进度怎么看：RUN_DIR=… python3 -I scripts/funnel.py RUN_DIR 生成 traces/funnel.md，列出 corpus → triage → extract → db → G 每一站的进出数和掉落原因。
  • 取成果：进 RUN_DIR/paper/。run3 的终稿在 paper/v3/：gold_paper_en.pdf（英文全文含附录）、gold_paper_zh.pdf（中文正文）、decision_guide_{en,zh}.pdf（决策指南）、changelog.md（每次改动的来源和数字）。

它怎么思考读懂流水线

一条固定的多阶段流水线，分成 6 个相位：下锚 → 证据地基 → 候选通解轮 → 试味与扩展 → 终局成文 → 构思与评估。设计原文见 docs/03_pipeline设计_22步.md（5 个阶段 22 步），运行入口见 pipeline/RUNBOOK.md 第 1 节阶段表。

核心 idea ① · 先拆后聚

剔除包装 → 带条件的事实 + 算子 DSL 方法程序 → 积木库 → 在积木层面找通解（设计原则第 3 条）。每个方法都写成 Gen / Comm / Revise / Critique / Loop / Stop / Share / Escalate / Agg / Tool 的程序，例如自一致性 k=9 写成 Gen(9,cot,same); Agg(vote)（config/schema.md 算子表）。

核心 idea ② · 多个提议者并行，互不读对方，裁判另请

提议 agent 按角度 P1–P3、R1–R4 并行出候选通解，互不读对方文件；审查 agent 不提新想法，最多补一条（RUNBOOK §2 第 3 条）。打分用 MDL 思路：通解要短，用它解释事实也要短，并在时间更晚的留出论文上有预测力（设计原则第 4 条）。终稿条数上限由 04_review 的 MAX_FINAL 设定（RUNBOOK 示例值 6；run3 v2 放到了 10 条）。

核心 idea ③ · 每条结论都要被反复敲打

按算力归一化比较（设计原则第 6 条）。之后再做以下敲打，有争议的结论只输出带边界的条件陈述（设计原则第 7 条）：

  • 留一组稳健性：scripts/robustness.py
  • 独立组荟萃：meta_analysis.py，I² ≥ 75% 时只能说「平均」
  • 发表偏倚回归
  • 测试重合度、矛盾对
  • 闭卷对照

核心 idea ④ · 洞见来自巨人镜头

除了从数据里炼通解，还用别人的眼光找新问题：

  • 汪浩然：借人类社会制度当多智能体的巨人肩膀，见 10_institution_catalyst.md；「升维看问题、低维出工具」，见 15_problem_lift.md。
  • ScholarCatalyst：作者当年怎么被前作启发，见 14_catalyst_ideation.md。
  • 凌杨：棋盘法找空格，见 scripts/chessboard.py 和 docs/10。

构思和查重分开做，构思 agent 不判自己的卡（RUNBOOK §2 第 6 条）。

第二层 · 每个模块的拆解

模块 1 · 下锚　定选题、中心问题、时间窗和锁定答案，跑起来后不再改（3 个阶段）

模块 3 · 候选通解轮　多个提议者并行提出通解，独立审查后留下终稿结论 G（4 个阶段）
模块 4 · 试味与扩展　不花钱地反复敲打每条 G：稳健性、复用、复现价值、矛盾（6 个阶段）
模块 5 · 终局成文　把 G 写成论文，溯源核对，翻译，出 PDF（9 个阶段）
模块 6 · 构思与评估　用巨人镜头出新设想卡，查重、勾选花钱；最后对照锁定答案评估（8 个阶段）

你在哪些点介入 · 5 个闸你的工作清单

每个闸只需要你做一个选择，或写一句意见；不需要你写代码。

★ 闸① · 菜单拍板

定选题、读者、时间窗、纳入排除、锁定答案。这一步决定后面所有 agent 看到什么，跑起来以后不再改。只回答一个问题：「菜单这样定，跑起来后不再改，可以吗？」

★ 闸② · 筛选边界

看 triage/lab_review_lenient.csv（宽松机构清单），决定删谁；需要补读图表的论文列在 figure_pass_candidates.tsv。只回答一个问题：「这些边缘论文算不算 solid？」

★ 闸③ · 终稿结论过目

审查后的 synthesis/final_candidates.json 加上打分。需要你定口径的分歧写在台账里，例如 2026-10-22 你定的「采样基线默认只认纯投票」。只回答一个问题：「每条 G 的边界你认不认？」

★ 闸④ · 出卡勾选与花钱

棋盘出卡后，打开 chessboard/decision_page.html 勾选，得到 decisions.json。凡是要调付费 API 的实验，先过 13_preapproval 跑前配置卡：本次配置、原论文配置、差异与理由、预算。等你同意才跑。只回答一个问题：「哪几张卡做？（花钱的先看配置卡）」

★ 闸⑤ · 是不是真金

读终稿 PDF 和决策指南。只回答一个问题：「这篇是不是值得精读的金子？」改动意见写进 paper/v3/changelog.md 的下一版。

和 TPL 的差距：TPL 的闸在 TUI 里弹清单、回车放行，还有全自动模式。我们的闸现在是主线程停下来问你，或者发你一个勾选页。统一闸门和全自动模式 🔭 B7。

输出目录详解每个文件夹是什么

① pipeline 目录 · 方法本身

模板、脚本、文档、台账。所有轮次共用，agent 一律不许读，因为里面有别的轮的结论和答案。

② 运行目录 · 一轮的全部

语料、筛选、抽取、库、综合、论文、留痕。init_run 时冻结的脚本快照也在这里，pipeline 后来再改，这一轮的结果不受影响。

③ 全文共享目录

paper_alchemy_fulltext/<id>.txt 加 pdf/，各轮共用。因为版权问题不上传 GitHub。

G1、G4 是什么？金子论文里的第 1、第 4 条通解。每条在 final_candidates.json 里有 level（本质机制 / 规律 / 边界）、可执行检验、支撑行。
为什么同一轮有好几个 db 目录？同一份抽取在不同口径下各建一库：db_pure_vote/ 是纯投票基线，db_corrected/ 是审查纠错层。原 db/ 永远不动，所以旧版论文的数字随时能复现。
被审查淘汰的候选还在吗？在。candidates_R*.json 和 notes_R*.md 全部保留；删掉的卡移到 _archive/，只归档，不删除。
怎么知道某个数字从哪来？正文数字 → final_scores*.json → 支撑行 → db/results.csv → extract/<id>.json 的 source（表号）。现在靠溯源 agent 抽查，🔭 B3 改为机器逐条核对。

常见问题与小技巧实用

实用小技巧

  • 先小后大：抽取先试抽 2 批，确认新字段都填上了、留痕一篇一行，再分波放量（2026-10-23 重抽 513 篇就是这么做的）。
  • 口径换了先另建库：改基线口径或纠错时，用 DB_DIR / 新目录另建库，再对比新旧 G 的数字。原库不动，旧版论文永远能复现。
  • 多看漏斗：哪一站掉的论文多，pipeline 就在哪里卡得紧。traces/funnel.md 一眼就能看出来。
  • case 收尾写台账：每跑完一个 case，把暴露的问题写进 docs/09_*。下一轮 pipeline 变好，靠的就是这本账。
